## Implementation

- `scripts/build-netlify.mjs` builds an allowlisted `dist/` static site. The public Membership page retains its information and all four original downloads, without the prototype form. Weather HTML/JS and all four PDF bytes are copied unchanged. Existing public content/weather functions remain intact.
- `netlify/functions/membership-pilot.mjs` is a supported JavaScript Functions v2 handler, with Node 22 configuration. It serves the private HTML at `/membership-pilot` and `/membership-pilot/*`. The direct `/.netlify/functions/membership-pilot` alias reaches the same checks. No Python process, SQLite file or writable Lambda filesystem is assumed.
- Every pilot page/application/PDF request requires server-validated HTTP Basic authentication using a scrypt password hash. Authentication is independent of Netlify's paid site-wide password feature. The rest of the website remains public. Fixed HTTPS origin, private/no-store responses, HttpOnly/Secure/SameSite cookies, CSRF tokens, honeypot, minimum completion time, persisted rate limits, 12 KB bodies and server validation provide additional controls. Use a private browser window and close it afterward to discard cached Basic credentials.
- `netlify/pilot/{domain,pdf,service}.mjs` ports the accepted validation, dues rules, original-background PDF overlay and accepted HTML/plain-text email. Phones normalize on blur and on the server; dates remain ISO internally and display as `Nov 14, 2026`. Review/Edit preserves entered answers; editing resets the PDF check. Long answers remain complete on the review sheet. The redistributable embedded Bitstream Vera font replaces the local Windows Arial dependency; its license is in `netlify/pilot-assets/`. The original first-page application remains unchanged underneath the overlay.
- Build assets are bundled under `netlify/pilot-private/` **inside the function**, outside `dist/`. `dist`, generated private assets, `.netlify`, environment files and databases are ignored. Do not deploy the repository root or upload local private review artifacts. The public blank application is intentionally still downloadable; completed applications never receive public document URLs.
- Private persistent storage uses **site-wide Netlify Blobs** store `cfe-membership-pilot-v1`, not the existing public-content `rc-flyers` store. Strong reads and conditional create/update writes protect sessions, rate counters and submissions across restarts/deploys. Missing write acknowledgments or ETags stop processing. The completed PDF, normalized data, dues and exact HTML/plain-text message are saved together before any delivery can be claimed. A stable HMAC reference deduplicates equivalent applications; keep the same secret across pilot deploys. Existing local accepted applications/history are not migrated.
- Save always holds email. George cannot enable delivery. The operator-only `/membership-pilot/api/send` additionally requires a separate operator token, `MEMBERSHIP_EMAIL_ENABLED=true`, and an exact authorized submission reference. Its durable compare-and-set claim allows one attempt; a failed/uncertain attempt is never automatically retried. HTTP status, redacted errors, provider ID and attempt state remain private. A crash after the claim leaves `sending`, requiring provider reconciliation. Provider acceptance is distinct from inbox delivery.
- Hosted sender is fixed to `membership@converseflyingeagles.org`; **the only recipient is `mg.farris@comcast.net`**. There are no CC/BCC, applicant confirmations or recipient overrides. Every message is a fictional test and contains matching stored PDF bytes. Mock-provider tests inspect the actual outgoing request. No live transport was called.

Netlify Blobs is shared across deploy contexts; it is not a relational transaction engine or an automatic-expiry database. Each application/email claim is a single conditional record operation. Sessions expire logically after one hour; expired sessions/rate counters and fictional submissions need explicit retention cleanup after the pilot. Agree a cleanup date, retain delivery reconciliation records as needed, then remove only this dedicated store. Do not delete the existing `rc-flyers` store.
